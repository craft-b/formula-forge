# Every transitive dependency, pinned. requirements.txt pins the packages the
# code imports; this pins what they pull in, so an install today and one in six
# months resolve the same tree. Applied automatically: requirements.txt
# references it with -c, so pip, CI, Docker and Render all honour it.
#
# Resolved for the deployed interpreter, Python 3.11 on Linux - not for
# whatever machine regenerates it. A first version was frozen from a 3.12 venv
# and pinned numpy 2.5.3 and Deprecated 3.0.0, both of which require 3.12; CI's
# install failed on them. Regenerate the same way, from any OS:
#
#   pip download --dest /tmp/dl --only-binary=:all: --python-version 3.11 #       --implementation cp --abi cp311 --platform manylinux_2_28_x86_64 #       --platform manylinux_2_17_x86_64 --platform manylinux2014_x86_64 #       --platform any -r requirements-dev.txt   # (with the -c line removed)
#
# and take name==version from the downloaded filenames.
#
# colorama is Windows-only (pytest's console colours); a constraint on a package
# that is never installed is inert.
