## Executive summary

FormulaForge today is a well-organized *demo*: a FastAPI + LangGraph service that regex-routes chat messages to either a RAG answer node or a formula-generation node, streams SSE to a clean React client, and has genuine test coverage (31 mocked tests) and CI. The top risks are all in the same place: **the system has no domain truth layer.** The "USDA database" contains food *names only* — zero nutrient data — so every nutrition number shown to users is an unvalidated LLM estimate dressed as data; nothing checks mass balance, and the dataset is 75% duplicate rows of branded products (not Foundation Foods as documented). Second-tier risks are an unauthenticated, un-rate-limited, CORS-open LLM endpoint (direct cost/abuse exposure) and a process-local session store that breaks under any horizontal scaling. The enterprise version inverts the trust model: the LLM proposes ingredient structures only; a deterministic calculation and constraint-validation engine — grounded in real composition data and ice-cream physics (mass balance, freezing-point depression, overrun) — verifies every formula before a user sees it. The full target design is in `docs/DESIGN_SPEC.md`.

## Top structural risks (narrative)

**1. Inverted trust model (F1+F2+F3).** The architecture treats the LLM as the source of nutritional truth and the "database" as decoration. Enterprise-grade is the exact inverse: a governed ingredient composition table is the source of truth; the LLM only proposes *structure* (which ingredients, what percentages, what rationale); deterministic code computes nutrition, checks mass balance and freezing-point behavior, and a constraint engine passes or rejects. Until that inversion happens, no other improvement matters — better retrieval or auth on top of fabricated numbers is polish on a hollow core. This is the organizing principle of the design spec.

**2. Uncontrolled cost/abuse surface (F4).** An open, streaming, LLM-backed endpoint with wildcard CORS is a standing invitation. One HN post away from a quota outage or a surprise bill. Cheap to fix now; expensive to discover in production.

**3. State that can't scale (F6+F10).** Process-local session state means the current system is architecturally capped at one process forever. Every scaling lever (workers, replicas, queue-based generation) is blocked behind externalizing one dict.

**4. The iteration dead-end (F7).** Formulation is inherently iterative; the current graph makes iteration silently wrong rather than explicitly unsupported. This is the largest *product* gap between demo and something a food scientist would adopt, and it shapes the orchestration redesign in the spec.

**5. Quality is untested where it's riskiest (F14).** The mocked test suite is genuinely good for what it covers — and covers none of the generative behavior the product is sold on. A golden-dataset eval harness (compliance accuracy, mass-balance pass rate, schema validity rate) run in CI is the single highest-leverage testing investment.
